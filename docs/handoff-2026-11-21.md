## Contract review against `docs/source/core-backend.txt`

This is a source review against the build document and tests, not an independent security audit. `docs/in-repo-core.md` already says these contracts are first implementations and must be audited before they hold real funds.

### Findings

1. **High — deployment script does not deploy or use the 48-hour timelock.** The build document §6.1 requires `AdminTimelock` for parameter changes and says the guardian can halt but cannot resume. `Deploy.s.sol` imports `AdminTimelock` but never constructs it; it passes the deployer EOA as the timelock to `HaltSwitch` and the other role-gated contracts (see `contracts/script/Deploy.s.sol`, around lines 82–100). In this deployment, the EOA can immediately resume, change roles, wire contracts, and change parameters, so the intended delay and guardian separation do not apply. The script also deploys mintable test tokens when token addresses are omitted; its comments warn this is for local/test only, but it has no mainnet chain guard.

2. **Medium — fee rounding destination differs from the documented invariant.** The build document §6.1 says rounding dust goes to `refundTo` (`docs/source/core-backend.txt`, around line 893). `FeeRouter.route` assigns the residual to the treasury (`contracts/src/Fees.sol`, around lines 64–76). This is a small amount per distribution but is a direct specification mismatch.

3. **Medium — dispute settings are not snapshotted as specified.** The build document §6.1 says fee basis points and the dispute window are snapshotted at funding (`docs/source/core-backend.txt`, around line 899). `RowSplit` stores the window when `openJob` runs (`contracts/src/RowSplit.sol`, `openJob`), while `disputeFeeMultiplier` is read from the current global value when a dispute is opened (`disputeRows`). A governance update between job opening/funding and dispute can therefore change the effective terms for that job.

4. **Low/Medium — dispute proof validation omits a row-index bound.** `RowSplit._challenge` verifies the Merkle proof and reservation state but does not reject `rowIdx >= rowCount` (`contracts/src/RowSplit.sol`, `_challenge`). A correctly formed off-chain tree should never contain such a row, but enforcing the index range on-chain would preserve the row-count invariant if a signed verdict or its tree is malformed.

### Documented gaps and design risks

- `CheckerNet` explicitly uses `block.prevrandao` for panel selection and does not penalize panelists who vote against the outcome (`contracts/src/Checkers.sol`, contract comment near line 141). The build doc/in-repo notes describe this as a first implementation; Foundry reports weak randomness.
- The Solana split program is deferred and is not present. `BurnBucket.bridgeOut` deliberately reverts until a bridge route is selected; both gaps are recorded as later-phase/day-one work in the docs.
- The 56 passing contract tests cover the current scenarios and fuzz money conservation up to 2,000 rows, but they do not establish standard ERC-8183 compatibility or replace an audit.
