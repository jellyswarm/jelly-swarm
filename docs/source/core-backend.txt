0. Hard rules (tests enforce each one)

1. No KYC/KYB code paths. Email is optional and used only to sign in. It is stored as
     an HMAC and never in plaintext (§10.1). There are no card fields. Onramps are third-
     party links the user picks.

2. Never hold user keys.
          Embedded wallets are passkey-controlled.
          The server never sees plaintext key material.
          Relayers can only move funds along fixed paths: vault → escrow for the vault's
          own owner, and escrow → payer for refunds.

3. Refunds and withdrawals are never gated.
           claimRefund / claim_refund on expiry can be called by anyone. They are never
          hookable, never pausable and never depend on a keeper.
           BalanceVault.withdraw is owner-only and works while the system is halted.
          Operator payout claims and checker unstake withdrawals are never pausable.

4. MAX_AGENTS = 247 concurrent workers per job. The hard USD cap is the quote.
     The budget guard refuses any call that would exceed it. Overruns go to the operator
     ledger and are never billed.

5. Fee split is fixed at 8000/1000/500/500 bps: worker operators / treasury /
     checker pay / buy-and-burn.
          Burns spend only fees from jobs whose funder is classified external.
          Every burn references its funding job ids.
          Free, credit and internal jobs never feed burns.

6. Untrusted input stays data. Peer-agent output, fetched pages and user chat are
     typed JSON data blocks. They are never concatenated into a system prompt and can
     never name a tool.

7. Planner, checker and merger never run on community nodes. Two kinds of job
     run only on TEE hosts:
          Sealed jobs.
          Any job whose items include a wallet address (an EOA on EVM, or a non-program,
          non-mint account on Solana).
8. Copy lint runs in CI. The build fails if any user-facing string contains APY, APR,
     yield, earn, passive income, guaranteed, partner or 24/7 . The 247 cap is always
     written as "of 247 agents". Always-on service is always written as "around the
     clock".

2.3 Router algorithm ( packages/gateway )

For each call:

1. Candidates. Start from the role's allowed models for the tier.
2. Filter by host policy:

          TEE-only for Sealed jobs and wallet jobs.
          The community pool only for role=worker ∧ tier=open ∧ !walletJob ∧
          product≠picket .

3. Filter by health. Drop hosts with circuit breaker open, error rate above 5% over 1
     min, or p95 latency above the SLO.

4. Rank by effective price, then by queue depth.
5. Reserve budget through budget-guard.
6. Call the OpenAI-compatible endpoint.
7. Settle the actual cost.
8. Emit the receipt (§4).

Fallback. Up to 2 alternative hosts, never crossing family for the checker. Offpeak
windows serve lane=deferred (§12.3).

3.2 Quote

The pricebook ( config/pricebook.ts ) is per product. Each entry has a baseUsd6 , a
unitUsd6 per tier, an optional minUsd6 , and a flatUsd6 .

Fanout:

quote = base 0.25 + pieces × {0.005 | 0.015 | 0.04} + toolsCap

Trawl:

Job                            Unit price                         Minimum
Token sweep (Standard)         $0.05                              $2
Token sweep (Sealed)           $0.15                              $5
Wallet sweep                   $0.50                              $2
Report                         flat $9                            —
Everyday list                  flat $3 (≤ 50 items) / $9 (≤ 247)  —

How minimums and flat prices are handled.

     Minimum. base = max(product.base, min − units × unit) . The base is charged
     only if at least one row passes.
     Flat prices. These become equal per-row slots, unit = flat / rows , so pay-on-
     pass still applies.
     Agents vs pieces. pieces is the item count. agents = min(pieces, 247) is
     concurrency. Items beyond 247 run in waves and are priced per piece. For example,
     600 items run as 3 waves.

toolsCap . This is the estimated paid data and tool spend at cost plus 10%, shown as its
own line. It is billed at actual cost (+10%) up to the cap. Tool spend on failed rows is
absorbed by us.

Dry run. The planner runs on a 5-item sample to fix the columns and per-row token
estimates. Then:

      estCost must be ≤ 70% of quote − fees (Muster's rule), or the job is downgraded
     or refused.
     The quote is EIP-712 signed by the quoter key: Quote{specHash, units, unitUsd6,
     baseUsd6, toolsCapUsd6, tier, maxAgents, expiresAt, chain} .

     The quote is valid for 10 minutes.

Step by step.

1. Quote (§3.2).
2. Fund. Exactly one of five routes:

          (a) A wallet signs JellyJob.fund .
          (b) The relayer calls BalanceVault.fundJob under the owner's SpendGrant .
          (c) x402: payTo is the job's IntakeForwarder (EVM) or the muster_split job
          vault ATA (Solana). Then a permissionless sweep or mark_funded runs.
          (d) Free tier or credits: the free-tier or credits wallet funds the job with
           beneficiary = account (§10.3).
          (e) ACP v2 payee mode through Muster's SwarmPayee .
           expiredAt = now + 2h + 1h per extra wave , at most 24h.

3. Fan out. BullMQ rows-<lane> (§12.3). The deterministic id is ${jobId}-${rowIdx}-
     ${attempt} . Rules:
          Concurrency per job is ≤ 247, enforced by a Redis semaphore.
          Worker loop cap: 12 tool calls and 4 LLM turns per row.
          Wall clock: 6 min per row.

4. Check (§3.4). A failed row gets one retry with a different host (same tier). If it fails
     again, the row is dropped ( refunded ).

5. Merge. The merger gets only passed rows, as typed data. It may only summarise
     and must not add facts. Any number in the summary must cite a row.

6. Seal. receipt-service builds the Merkle root over the job's receipts and calls
      ReceiptRoot.seal (EVM) or muster_split.anchor_receipts (Solana).

7. Settle.
          The checker key signs Verdict{jobKey, rowCount, passedCount, rowsRoot,
          receiptsRoot, toolsUsd6} .
          The keeper calls RowSplit.settle .
          The refund goes out immediately: (rowCount − passedCount) × unit + (toolsCap
          − tools) , plus the base if passedCount == 0 .
          Gross is held for the dispute window (24h by default).

8. Audit and dispute. settlement-keeper opens a Muster CheckerNet Audit round,
     panel of 3, for 5% of jobs plus every job ≥ $50. A client dispute names up to 25 row
     indexes and pays one fee: Muster's max($0.50, 1%) × multiplier on the summed
     pending amount. If an audit or dispute reverses a pass:
           that row's unit is refunded on the 100/75/35/0 curve;
           the verdict signer's bond is slashed 10%.

 9. Finalize and split. After the window, anyone can call finalize . Gross splits 80% →
       OperatorPayouts , 10% → treasury, 5% → checker bucket, 5% →
       BurnBucket.accrue(jobKey) .

10. Expiry path. If the job was never settled, anyone can call claimRefund after
       expiredAt and gets 100% back. No hook, no pause, no keeper.

3.4 Checker pipeline ( packages/checker )

Deterministic checks. These run first, in order:

1. Schema. Validate the row against the column zod types.
2. Source fetch.

          Fetch the cited URL through the same robots-respecting fetcher.
          Normalise the HTML to text (NFKC, whitespace collapse).
          Require quoteSpan to be present.
          Require the cell value to appear in the span or be derivable from it (numbers
          within 0.5%).

3. Chain read. Re-run chainRead (viem readContract / Helius DAS) at the latest block
     and compare. Time-varying values (holder share, liquidity) get a tolerance.

4. Fail closed. Any needsSource cell without a source becomes "unverified" , and the
     row still passes only if ≥ 80% of its sourced cells pass.

Judge. GLM-5.3 Flash gets the spec, the cells and the fetched spans, never the
worker's reasoning. It answers {pass, failingCells[], reason} .
Retry routing. If the judge fails a row that the deterministic checks passed, the row is
re-run once on a different host.

Accuracy target (M3 test): ≥ 95% of planted errors caught and ≤ 3% false rejects.

Muster's ReceiptLog. The seal stores (root, count, head) .

Signer. One gateway receipt key per deployment, held in a Phala CPU TEE. Workers are
ephemeral, so per-agent keys are not used. Calls from community nodes also carry the
node's own signature over outputHash .

Scope.

     metric.
     Canary rate: 2% of calls.

3. Three strikes means removal.
4. Detection target: a swapped model is caught within 50 calls (M7 test).

     A node is credited only for rows that passed: credit = unit × 80% × (node's calls

      OperatorPayouts takes a daily Merkle root of (operatorId, amountUsd6) .
     Claims are paid in USDC, are permissionless and are never pausable.
     There are no emissions.
     Until outside operators exist, all 80% routes to studio operator ids, and /stats says
     so.

Exit. requestExit starts a 7-day cooldown, then withdrawStake , which is never
pausable.

10.1 Sign-in options (one accounts row and several identities)

1. Anonymous ("just open the page").
          The server issues a signed device cookie ( devices.id , HMAC, 1-year).
          The browser solves a PoW challenge (§10.3) before the first quote.
          The account is created lazily on first job.

2. Passkey (WebAuthn). Resident credential with userVerification: required . This
     is the default for anyone who will hold money, because it also controls the embedded
     wallet.

3. Email link.
           emailStart sends a one-time link (15 min, single use) through a self-hosted
          SMTP relay (provider TBD, day 1).
          We store only HMAC(pepper, lowercase(email)) . The plaintext is held in memory
          for the send and never written.
          Email-only accounts can run free and credit jobs. Funding money requires
          creating a passkey wallet or connecting an external wallet.

4. External wallet. SIWE / SIWS, as in Muster.
5. Telegram. See §12.2.

Identities merge only when a signed-in session proves both of them. There is no merge
by email lookup.

EVM (Base, RHC).

16. Honest limits

Proof and independence.

     Studio-signed receipts. On Open and Standard, receipts prove our claims, not the
     hardware. Only Sealed carries TEE attestation.
     Independence is procedural at launch. The studio runs both checkers and
     workers. "Independent" means a separate key, operatorId and model family. /stats
     discloses this, and the 80% goes to studio operators.
     Fast-path settlement trusts one bonded checker signature. Only 5% of jobs
     (plus every job ≥ $50) get a panel audit. A bad verdict on an unaudited small job is
     caught only by a client dispute. The $0.50 minimum dispute fee makes single sub-$1
     rows uneconomic to dispute, which is why up to 25 rows can be batched per dispute.
     Fingerprinting is probabilistic. Thresholds are calibrated, not proven. A clever
     node could pass canaries and cheat on rare calls, and the 5% re-run reduces that
     risk without removing it.

Payments and chains.

     x402 is tiny (~$2,815/day on 21 Oct). Prepaid vaults and passkey wallets will carry
     revenue.
     Cross-chain burns depend on bridges we have not chosen. Until then, buckets
     accrue and are disclosed.
     Volume and venues. RHC activity is reportedly down about 42% (headline only).
     Elysium is unproven.
     ACP v2 payee mode inherits ACP v2's refund rules, not ours.

Retail flows.

     Embedded wallets depend on unverified primitives. P-256 on RHC and
     secp256r1 on Solana are unchecked. The Solana fallback keeps a wrapped key in
     browser storage: if the user loses every passkey and the backup, the funds are
     unrecoverable by design.
     Email sign-in needs a mail relay. The relay operator may require an account on the
     studio side. Users' emails never persist. Onramps may require ID from the user. We
     never see it, but users may read it as "this app asked for ID", so the copy must say
     the onramp is a third party.
     The free tier is a cost centre. PoW and device/IP limits slow farming, but cannot
     stop it: residential proxies and fresh browsers get through. The global free budget is
     the real cap.
     Load behaviour is modelled, not measured. Router capacity under 250-call
     bursts is unknown until the day-1 load test, and peak days will show long free-tier
     ETAs.

Costs and outputs.

     Costs are modelled. The 2.65M-token job and the 8K/1.5K per-call figures are
     assumptions. If real contexts are 2x longer, costs double, and quotes still hold.
     Wrong cells remain possible. Deterministic checks catch fabricated sources but
     not every misread. "Unverified" beats a wrong value, and spot audits measure the
     rest (the day-30 target is a cell error rate under 3%).
     Directory listing in Claude and ChatGPT is unverified for anonymous
     publishers. URL install works.
